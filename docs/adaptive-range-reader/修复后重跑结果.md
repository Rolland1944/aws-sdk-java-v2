# 修复 renderer 后的 COS 重跑结果

> 更新：2026-11-06。本文只记录 encoding / dictionary 修复之后新写出的布局，以及在这些布局上新跑的 2×2 网格。
> 旧网格、旧 COS 前缀和 `EVALUATION.md` 里的已发表数字保持原样，用作修复前的对照。
> 口径与 `EVALUATION.md` 相同：墙钟取每格 `query_sum_s` 的中位数；CV 为样本标准差除以均值；GET 取 `io.gets` 的中位数，远端字节取 `io.remote_bytes` 的中位数。
> 正式比较要求 n=5 且 CV<5%。Criteo 与 NYC 是 3 轮试跑，不能替换 2026-10 的正式中位数。

修复点有两处。显式非 dictionary encoding 只作用于被点名的列，不再把 `use_dictionary` 清空。未点名列保持源 footer 里一致的 dictionary 策略：源上全是 dictionary 的列继续使用 dictionary，源上全不是的列继续不用。计划本身没有重搜，四组都物化各自已经冻结的 deterministic plan。几何门在上传前通过；行组数与源行数均与计划一致。

四组都在腾讯云 COS `ap-guangzhou` 上跑，Spark `local[16]`。Track1 为固定 4 GiB adaptive D1，doorkeeper 关闭，admit-bytes 为 0，block 为 1 MiB。00/01 走原生 S3A，10/11 打开 Track1。轮次在四格之间轮换。

尚未重跑、因此不在本文取数：NovoMCP（计划里没有显式 encoding）、TPC-H SF350（显式 encoding 只在 `partsupp`）、TPC-H SF100 的 encoding 消融，以及全部 AWS 网格。
